# Agent Prompts

This documentation is designed to be self-contained when symlinked as `supex-docs/` in a project.

This directory contains documentation and prompts for AI agents that interact with SketchUp via Supex MCP tools.

It covers two authoring workflows:
- Ruby workflow for direct SketchUp API automation
- VCAD workflow for parametric CAD in Loon (`.skp.oo` + `.oo` modules)

### Purpose

When an AI agent (Claude, etc.) works on a SketchUp project using Supex, it needs guidance on:
- How to choose Ruby vs VCAD for the task
- How to use the MCP tools (`eval_ruby_file`, `vcad_place`, `vcad_place_with_imports`, etc.)
- SketchUp Ruby API patterns and best practices
- Loon `.skp.oo` authoring constraints and VCAD update workflow
- Reusing existing CAD library modules instead of writing ad-hoc geometry helpers
- Common pitfalls and how to avoid them

These files provide that context. They are designed to be included in agent system prompts or referenced during conversations.

### Structure

```
docs/agents/
├── prompt.md          # Main agent prompt (comprehensive)
├── workflow.md        # Extended workflow examples
├── best_practices.md  # Geometry pitfalls and troubleshooting
├── api/               # SketchUp Ruby API docs (symlink)
├── stdlib/            # Standard library helpers (symlink)
└── README.md          # This file
```

**Note on symlinks**: `api/` and `stdlib/` are symlinks that may point outside this project. When reading files from these directories as an agent, use direct paths like `supex-docs/stdlib/README.md` rather than glob searches, as glob tools typically don't follow symlinks across directory boundaries.

### File Descriptions

- **prompt.md** - Source-of-truth prompt for both Ruby and VCAD workflows. This is the primary document agents should read.
- **workflow.md** - Extended workflow examples for Ruby and VCAD authoring.
- **best_practices.md** - Cross-workflow troubleshooting and guardrails.
- **api/** - SketchUp Ruby API markdown docs available through the local `supex-docs/api/` path.
- **stdlib/** - Reusable utility functions for geometry, entities, and colors. Agents should prefer these over writing custom helpers. See `supex-docs/stdlib/README.md` for API reference.

### Usage

**In example projects**: Reference these docs in the project's agent configuration:
```markdown
For SketchUp modeling guidance, see: supex-docs/prompt.md
```

**In custom prompts**: Include or reference `prompt.md` as the primary source of SketchUp modeling instructions.

### Maintenance

- `prompt.md` is the source of truth for agent behavior
- `api/` is auto-generated by `docgen/` - do not edit directly
- When adding new MCP tools, update the Tools Reference section in `prompt.md`
- Keep naming consistent: use `VCAD` in prose and lowercase `vcad_*` in identifiers
